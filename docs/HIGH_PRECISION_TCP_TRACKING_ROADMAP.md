# High-precision TCP tracking roadmap

Date: 2026-09-02

This document preserves the current Visual Whole-Body Control (VBC)-inspired
scheme as a reproducible baseline and records the preferred direction for
higher-precision B2-W + Z1 TCP tracking. The VBC baseline remains useful for
visual task planning and learned body coordination, but its basic Jacobian IK
is not the final precision controller for lever-handle door manipulation.

## Preserved VBC-inspired baseline

The preserved baseline contains:

- a base-mounted `head_cam` and a wrist-mounted `z1_cam`;
- a two-view 96 x 54 target-mask and segmented-depth interface;
- a slow visual policy that outputs TCP pose increments, base forward/yaw
  commands, and a binary gripper command;
- a learned leg policy for velocity, balance, height, and posture adaptation;
- an arm controller that converts a 6D TCP error into joint targets with
  damped pseudoinverse Jacobian IK.

The original VBC architecture runs its vision planner at about 6.25-8.33 Hz,
its quadruped policy at 50 Hz, and its real-arm IK loop at about 800 Hz. It is a
strong reference for hierarchical learning, but the reported goal-reaching
errors are too large to use as the only controller for precise handle
alignment: approximately 4.7 cm / 0.850 rad while standing and 2.9 cm /
0.332 rad while walking.

## Target architecture

The visual system and high-precision controller should be separated by a
smooth reference manager:

```text
head + wrist RGB-D (30 Hz)
        -> object/handle pose and uncertainty
        -> task policy / door state machine (8-15 Hz)
        -> world- or door-frame TCP subgoal
        -> reference governor (100-200 Hz)
        -> constrained whole-body QP (200-500 Hz)
        -> joint torque/position loops (500-1000 Hz)
```

Images select and update the task-space goal. They must not directly replace
the fast proprioceptive TCP servo.

## Task-space error

Use a geometric SE(3) error instead of subtracting Euler angles:

```text
e_position = p_target - p_tcp
e_rotation = Log(R_target * R_tcp^T)
e_tcp      = [e_position, e_rotation]
```

The target twist should be generated by a bounded, critically damped reference
filter. Position and orientation velocity/acceleration limits must be applied
before the whole-body solve. A small terminal deadband and hysteresis prevent
the controller from switching modes repeatedly around the target.

## Whole-body QP

The QP should coordinate the floating base, twelve leg joints, four wheels,
and six arm joints. A velocity-level QP is acceptable for the first milestone;
a torque/acceleration-level inverse-dynamics QP is the final target.

Hard constraints:

- joint position, velocity, acceleration, and torque limits;
- wheel rolling/no-lateral-slip constraints;
- wheel-ground contact and friction limits;
- self-collision, arm-body collision, and ground-clearance limits;
- safe base roll, pitch, and height envelopes;
- command-rate limits and a safe fallback when the solve is infeasible.

Prioritized soft objectives:

1. contact consistency, balance, and collision avoidance;
2. TCP position and orientation tracking;
3. base relocation and posture changes that restore arm reachability;
4. arm manipulability, joint-centering, and distance from singularities;
5. nominal posture, smoothness, and energy.

Use adaptive damping or task weights near singular configurations. Integral
correction, if needed, should operate only near the target and use anti-windup;
it must not push against joint, collision, or reachability constraints.

## Role of reinforcement learning

RL should learn the slow coordination decisions that are difficult to encode,
not replace the precision servo. A policy can propose:

- base forward/reverse velocity and yaw rate;
- body height, pitch, and optional roll targets;
- reachability-aware posture or QP-weight residuals;
- door phase and gripper state;
- bounded residual TCP twist.

The constrained WBC remains responsible for exact tracking and safety. This
preserves VBC's useful emergent crouching/rising behavior while avoiding the
large terminal error and joint-limit problems of unconstrained pseudoinverse
IK.

## Door-specific control modes

The door task should not use one pose controller for the entire episode:

1. **Approach:** visual base alignment and collision-aware TCP tracking.
2. **Pre-grasp:** high-gain but velocity-limited SE(3) tracking in the handle
   frame.
3. **Grasp:** close the gripper and switch to compliant Cartesian control.
4. **Turn:** constrain motion around the estimated handle axis while regulating
   radial error and contact force.
5. **Pull:** maintain the grasp/handle constraint, command negative base
   velocity, and regulate tension rather than holding one rigid world pose.
6. **Traverse/release:** coordinate door clearance, base path, arm posture, and
   gripper release.

After contact, hybrid motion/force or impedance control is more important than
minimizing an unconstrained absolute TCP pose error. Joint-torque estimates or
a wrist force/torque sensor should enter the contact controller.

## Initial acceptance targets

Measure position and orientation separately rather than reporting one reward:

| Test | Position target | Orientation target |
|---|---:|---:|
| Static reachable setpoints in simulation | <= 5 mm RMS | <= 2 deg RMS |
| Moving target with a stationary base | <= 10 mm RMS | <= 5 deg RMS |
| Whole-body relocation/tilt tracking | <= 15 mm RMS | <= 7 deg RMS |
| Door pre-grasp terminal error | <= 10 mm | <= 5 deg |

Also record settling time, overshoot, 95th-percentile error, TCP jitter after
settling, minimum collision distance, manipulability, QP infeasibility rate,
wheel slip, and base attitude. Real-robot tolerances can be relaxed only after
measuring calibration and perception uncertainty independently from control
error.

## Precision during whole-body motion

Arm repeatability must not be confused with mobile world-frame TCP accuracy.
The approximate error budget is:

```text
world TCP error
    = base pose/state-estimation error
    + arm tracking error
    + mount, joint-zero, and TCP calibration error
    + structural compliance and payload deflection
    + sensing, network, and control latency
    + target perception and hand-eye calibration error
```

At 0.7 m reach, one degree of uncorrected base attitude error produces about
12 mm of translational TCP error. The Z1 manufacturer quotes approximately
0.1 mm repeatability but explicitly notes that accuracy depends on test
conditions and that insufficiently optimized position control can produce
large error and shaking because whole-arm stiffness is low. That repeatability
number is therefore not a whole-body tracking guarantee.

Use these as planning ranges until a B2/B2-W + Z1 benchmark replaces them with
measurements:

| Operating mode | Simulation RMS target | Real-hardware RMS estimate |
|---|---:|---:|
| Standing, arm motion only | 3-8 mm, 1-2 deg | 5-15 mm, 1-3 deg |
| Slow coordinated walking | 10-25 mm, 2-5 deg | 20-50 mm, 3-8 deg |
| Contact transition, slip, fast gait, or difficult reach | 20-50 mm transient | 50-100+ mm transient |

The current acceptance target of 15 mm / 7 degrees for simulated relocation is
ambitious but reasonable for a slow, coordinated controller. It is not a claim
about the current LeggedManip checkpoint or future hardware performance.

Door manipulation should use explicit accuracy phases:

1. transit with a loose tracking envelope;
2. approach below roughly 0.1-0.15 m/s base speed;
3. stop and require a measured 0.3-1.0 s stable window;
4. execute the last 10-20 mm arm-dominant motion at roughly 20-50 mm/s;
5. switch to 5-20 mm/s Cartesian impedance/admittance motion after contact;
6. permit only slow base creep while regulating handle force and tension.

This `move -> settle -> grasp -> compliant pull` sequence is preferable to
rigid high-gain world-pose tracking while trotting.

## Isaac Lab training and randomization curriculum

Register a separate `B2-Z1-TCP` task rather than changing the upstream
`B2-Z1-WBC` baseline. Use world-frame FK-derived goals, desired TCP twist, and
a low-dimensional learned coordinator around a frozen GPU-batched DIK/OSC or
constrained WBC. For footed B2 the macro action is
`[vx, vy, yaw_rate, body_height, body_pitch]`; omit `vy` for B2-W. Never sample
an unrelated base-velocity objective.

Promote training using held-out tracking metrics rather than PPO reward alone:

| Stage | Distribution | Promotion evidence |
|---|---|---|
| 0. Lower-controller validation | Nominal plane; no RL, noise, delay, payload, or pushes | Stable local SE(3) tracking with no invalid state |
| 1. Static coordination | FK-derived static goals; mostly local plus small ghost-base displacement | >95% held success and >99% survival |
| 2. Moving goals | Minimum-jerk/spline pose and twist; speed raised gradually | Moving RMS and P95 pass on unseen seeds |
| 3. Relocation | Increase ghost-base translation/yaw and orientation diversity | Relocation passes without unnecessary base motion |
| 4. Mild DR | Flat ground; small dynamics, sensing, and delay uncertainty | >90% success; nominal regression below 15% |
| 5. Measured DR | Payload/COM, deployment uncertainty, latency, modest pushes | Three or more seeds; saturation below 1% of steps |
| 6. Terrain | Plane, friction patches, millimetre roughness, then mild slopes | Terrain passes while flat regression stays below 15% |
| 7. Frozen evaluation | Held-out goals, seeds, parameter corners, and stress cases | Select by complete metric matrix, not reward |

Suggested initial randomization ranges are deliberately narrower than the
current upstream defaults:

| Parameter | Mild | Full starting envelope |
|---|---:|---:|
| Floor friction | 0.7-1.1 | about 0.4-1.2, then replace with measurements |
| Link mass | +/-5% | +/-10% |
| Inertia | +/-5% | +/-15% |
| Base COM | +/-1 cm XY | up to +/-3 cm XY |
| Motor/PD gains | +/-10% | +/-20% |
| Actuator delay | 0-10 ms | 0-20 ms |
| Joint position noise | +/-0.005 rad | +/-0.01 rad |
| Joint velocity noise | +/-0.2 rad/s | +/-0.5 rad/s |
| Estimated TCP noise | +/-2 mm, +/-0.5 deg | +/-5 mm, +/-1 deg |
| Payload | none | ramp through measured mass, COM, and inertia |
| Pushes | none | modest horizontal disturbances, added last |

Keep approximately 20% of environments nominal during full randomization to
anchor precision. Do not assume wider randomization is better; replace these
provisional envelopes with distributions measured from the real platform and
avoid counting the same actuator/pipeline latency twice.

For an indoor door deployment, the final terrain mixture should remain mostly
flat: approximately 70% perfect plane, 20% low height variation starting near
+/-5 mm and capped near +/-10 mm, and 10% slopes up to about +/-3 degrees.
Avoid stairs and rubble unless they match deployment. Add a terrain height
scanner before training on geometry larger than roughly 1-2 cm. Visual texture
and lighting augmentation matters only after camera observations enter the
actor.

## Implementation order

1. Build a repeatable static and moving SE(3) tracking benchmark.
2. Replace Euler-angle orientation control with SO(3) logarithmic error.
3. Add target filtering, terminal hysteresis, adaptive damping, and null-space
   joint-centering to the arm-only controller.
4. Integrate joint, collision, rolling, and base-posture constraints into one
   QP and validate unreachable targets.
5. Train a slow reachability/posture coordinator in Isaac Sim while keeping the
   QP frozen.
6. Add handle-frame impedance and force-aware turn/pull modes.
7. Only then connect the dual-camera visual policy and perform sim-to-real
   calibration and randomization.

This roadmap intentionally keeps the VBC camera and learning ideas available
without accepting VBC's tracking precision as the final performance ceiling.
